= Neo4j Debezium Converter

:toc:
:toc-placement: macro
:linkattrs:
:icons: font
:source-highlighter: highlight.js

toc::[]

The `Neo4jDebeziumConverter` SMT converts Neo4j CDC change events into the {prodname} change event envelope, enabling CDC pipelines from Neo4j to relational databases via the {prodname} JDBC sink connector:

[source]
----
Neo4j -> Neo4j source connector (CDC) -> Kafka -> [Neo4jDebeziumConverter] -> Debezium JDBC sink -> RDBMS
----

It is the inverse of the xref:transformations/neo4j-cud-converter.adoc[Neo4j CUD Converter]: together the two keep a graph database and a relational database in sync in either direction.

The SMT is stateless and processes one message at a time.
It is *zero-config by default*: Neo4j CDC events are self-describing, so the SMT derives the target table, primary key, and columns from each event.
Every configuration option is an optional override and allow customization to be compliant with sink db.

For each change event the SMT emits a new record whose:

* value is a {prodname} envelope `Struct` (`before`, `after`, `source`, `op`, `ts_ms`),
* key is a primary-key `Struct`
* topic is set to the derived target table name, so a JDBC sink configured with `collection.name.format=${topic}` writes to the right table.

[NOTE]
====
This SMT expects a schema-typed `Struct` value produced by a Neo4j source connector in `EXTENDED` payload mode (for example via the Avro or JSON-with-schema converter).
A record whose value is not a Neo4j CDC event `Struct` passes through *unchanged*, so the SMT is safe to place on a shared topic.
====

[[neo4j-debezium-converter-nodes]]
== Node mapping

A node change event maps to a row in the table named after the node's label (subject to `table.naming` or a `label.<Label>.table` override).

The primary key is derived from the node's `keys` entry, which the Neo4j source connector populates from the label's key or uniqueness constraint.
Override it with `label.<Label>.key.properties` when no constraint exists or a different key is desired.

Node properties become columns, renamed by `column.naming`.
Use `label.<Label>.properties.include` or `label.<Label>.properties.exclude` to select columns; the key columns are always retained.

Operations map directly: `c` -> `c` (with `after`), `u` -> `u` (with `after`), `d` -> `d` (with `before`).

[[neo4j-debezium-converter-multi-label]]
=== Multi-label nodes

A node may carry several labels.
The SMT resolves the *owning* label (and therefore the target table and key) as follows:

* If exactly one of the labels has a `label.<Label>.*` mapping, that label owns the row.
* If the node has a single label and no mapping, that label owns the row by convention.
* If a multi-label node has no mapped label, or more than one mapped label, the owner is ambiguous and the record is handled per `field.missing.behavior`.

[[neo4j-debezium-converter-relationships]]
== Relationship mapping

A relationship change event is mapped in one of two modes, selected per relationship type with `relationship.<TYPE>.mode`.

[[neo4j-debezium-converter-join-table]]
=== Join-table mode (default)

The relationship becomes a row in a join table named after the relationship type.
The two endpoint keys become the composite primary key (foreign-key columns), and the relationship properties become the remaining columns.

Each endpoint column name is composed from the endpoint label and its key property according to `relationship.fk.naming` (for example `Order` + `id` -> `Order_id`), then cased by `column.naming`.
For a single-key endpoint you can override the column name directly with `relationship.<TYPE>.start.column` / `relationship.<TYPE>.end.column`.

A relationship delete emits `op=d` keyed by the two endpoints.

[[neo4j-debezium-converter-foreign-key]]
=== Foreign-key mode

The relationship becomes a foreign-key column update on the *owner* endpoint's table (default: the `start` endpoint; set `relationship.<TYPE>.owner=end` to make the end endpoint the owner).

The event is always emitted as a partial update (`op=u`): the `after` image contains the owner's primary key plus the foreign-key column pointing at the other endpoint's key.
On a relationship delete the foreign-key column is set to `null` (still `op=u`), clearing the reference.

The foreign-key column name follows `relationship.fk.naming` + `column.naming`, or the `relationship.<TYPE>.fk.column` override.

[[neo4j-debezium-converter-qualified]]
=== Qualifying a relationship by endpoints

The same relationship type can connect different endpoint labels.
To map a specific pair, qualify the type with `@<Start>-<End>`, for example `relationship.KNOWS@Person-Person.table=friendships`.
A qualified mapping takes precedence over the unqualified `relationship.<TYPE>.*` fallback for matching endpoints.

[[neo4j-debezium-converter-type-mapping]]
== Type mapping

In `EXTENDED` payload mode the Neo4j source connector wraps every property value in a self-describing type union.
The SMT reads that union and maps each Neo4j property type to the Kafka Connect / {prodname} column type the JDBC sink can persist.
Neo4j primitives map by identity, Neo4j temporals become the matching `io.debezium.time.*` logical types, and values with no flat relational representation (durations, spatial points, and structured lists) are serialized to a JSON `STRING`.
Every mapped column is optional so the sink can persist nulls (primary-key columns are made required).

[NOTE]
====
The `io.debezium.time.*` logical types produced here (`Date`, `MicroTime`, `Timestamp`, `ZonedTime`, `ZonedTimestamp`) are the {prodname} temporal types the JDBC sink already understands, so it materializes them as the corresponding native SQL column types.
`LocalDateTime` values are interpreted at UTC; `Time` and `DateTime` keep their original zone offset.
====

[[neo4j-debezium-converter-tombstones]]
== Tombstone handling

A tombstone record (null value) is passed through unchanged by default so downstream delete semantics are preserved.
Set `tombstones.enabled=false` to drop tombstones instead.

[[neo4j-debezium-converter-limitations]]
== Limitations

* *Primary-key value changes are not supported.* A stateless one-record SMT cannot represent a key change as the delete+create pair the JDBC sink expects, so an update that changes a key value is handled per `field.missing.behavior`.
* A node label with no `keys` entry (no Neo4j key/uniqueness constraint) yields no portable primary key; provide `label.<Label>.key.properties` or the record is handled per `field.missing.behavior`.
* The SMT requires schema-typed `Struct` values (`EXTENDED` payload mode); schemaless `Map` values are not supported.

[[neo4j-debezium-converter-source-connector]]
== Recommended Neo4j source connector configuration

The SMT consumes the events emitted by the https://neo4j.com/docs/kafka/[Neo4j Kafka source connector].
For the SMT to work, that upstream connector must be configured to produce *self-describing, schema-typed CDC events*.
The settings below are the ones the SMT relies on, all other Neo4j connector options can be set as usual.

.Recommended Neo4j source connector settings
[cols="35%a,20%a,45%a",options="header"]
|===
|Property
|Recommended value
|Why

|`neo4j.source-strategy`
|`CDC`
|The SMT reads Neo4j Change Data Capture events. Query-based strategies do not produce the CDC event shape the SMT expects.

|`neo4j.payload-mode`
|`EXTENDED`
|*Required.* `EXTENDED` wraps every property value in a self-describing type union, which the SMT needs to map Neo4j temporal, spatial, and array types to the correct relational columns. The `COMPACT` mode drops this type information.

|`value.converter`
|A schema-typed converter
|Use Avro (`io.confluent.connect.avro.AvroConverter`) or JSON with schemas enabled (`org.apache.kafka.connect.json.JsonConverter` with `value.converter.schemas.enable=true`) so the SMT receives a typed `Struct`. Schemaless values pass through unchanged.



|`neo4j.cdc.topic.<topic>.key-strategy`
|`SKIP`
|The SMT derives its own primary-key record key from the change event, so the source connector need not compute one.
|===

CDC must also be enabled on the Neo4j database itself (CDC is a Neo4j *Enterprise* feature)

A minimal source connector configuration that produces events this SMT can consume:

[source,json]
----
{
  "connector.class": "org.neo4j.connectors.kafka.source.Neo4jConnector",
  "neo4j.uri": "bolt://neo4j:7687",
  "neo4j.authentication.type": "BASIC",
  "neo4j.authentication.basic.username": "neo4j",
  "neo4j.authentication.basic.password": "<password>",
  "neo4j.database": "neo4j",
  "neo4j.source-strategy": "CDC",
  "neo4j.start-from": "EARLIEST",
  "neo4j.payload-mode": "EXTENDED",
  "neo4j.cdc.topic.persons.patterns": "(:Person)",
  "neo4j.cdc.topic.persons.key-strategy": "SKIP",
  "key.converter": "org.apache.kafka.connect.json.JsonConverter",
  "value.converter": "org.apache.kafka.connect.json.JsonConverter",
  "value.converter.schemas.enable": true
}
----

[[example-neo4j-debezium-converter]]
=== Examples

==== Zero configuration

With no options, the SMT maps each node to a table named after its (single) label, keyed by the label's constraint key:

[source]
----
transforms=neo4j
transforms.neo4j.type=io.debezium.transforms.Neo4jDebeziumConverter
----

A `Customer` node with key `id` is written to a `Customer` table keyed by `id`.

==== Snake-case naming for a relational sink

[source]
----
transforms=neo4j
transforms.neo4j.type=io.debezium.transforms.Neo4jDebeziumConverter
transforms.neo4j.table.naming=snake_case
transforms.neo4j.column.naming=snake_case
----

An `OrderItem` node becomes an `order_item` table; a `unitPrice` property becomes a `unit_price` column.

==== Join-table relationship

Map a `CONTAINS` relationship between `Order` and `Product` to an `order_items` join table:

[source]
----
transforms=neo4j
transforms.neo4j.type=io.debezium.transforms.Neo4jDebeziumConverter
transforms.neo4j.column.naming=snake_case
transforms.neo4j.relationship.CONTAINS.table=order_items
transforms.neo4j.relationship.CONTAINS.properties=quantity
----

Each `CONTAINS` event becomes an `order_items` row with columns `order_id`, `product_id`, and `quantity`, keyed by (`order_id`, `product_id`).

==== Foreign-key relationship

Map a `PLACED_BY` relationship from `Order` to `Customer` as a foreign key on the `orders` table:

[source]
----
transforms=neo4j
transforms.neo4j.type=io.debezium.transforms.Neo4jDebeziumConverter
transforms.neo4j.column.naming=snake_case
transforms.neo4j.relationship.PLACED_BY.mode=foreign_key
transforms.neo4j.relationship.PLACED_BY.table=orders
----

Each `PLACED_BY` event becomes a partial update (`op=u`) of the `orders` row identified by `id`, setting the `customer_id` foreign-key column. A relationship delete sets `customer_id` to `null`.
